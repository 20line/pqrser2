# Avito Watcher Bot

Персональный инструмент для одного пользователя: следит за появлением новых
объявлений на Avito по сохранённым поисковым запросам и присылает
уведомления в Telegram. Управление ботом (добавление/удаление товаров,
пауза, настройки) происходит через inline-меню того же Telegram-бота.

Реализация соответствует ТЗ `avito_bot_spec.md`: анонимный доступ к Avito
без логина, Playwright с persistent-профилем без headless-режима,
общий бюджет запросов вместо линейного роста частоты проверок,
антидетект-паузы, обработка капчи с экспоненциальным бэкоффом,
SQLite как единственное хранилище состояния.

## Технологии

- Python 3.11+
- [Playwright](https://playwright.dev/python/) (Chromium, persistent context)
- [aiogram 3](https://docs.aiogram.dev/) — Telegram-бот с inline-кнопками
- SQLite (`aiosqlite`) — единственное хранилище состояния
- BeautifulSoup4 — разбор DOM карточек объявлений

## Структура проекта

```
avito_watcher/
  config.py           # статическая конфигурация из .env (токен, owner_chat_id, пути)
  models.py            # датаклассы: Profile, GlobalSettings, ListingCard, ...
  db.py                 # SQLite-слой: профили, seen_listings, настройки, журналы
  settings_cache.py      # in-memory кэш GlobalSettings поверх db.py
  scheduler.py            # round-robin очередь + общий бюджет запросов (п.7 ТЗ)
  parser.py                # извлечение карточек объявлений из HTML Avito
  captcha.py                # эвристики обнаружения капчи/блокировки
  watcher.py                 # Watcher Engine: основной цикл проверки (п.6, п.8 ТЗ)
  notifications.py            # форматирование уведомлений + digest-режим
  logging_setup.py             # логирование с ротацией (п.13 ТЗ)
  app.py                        # сборка: Telegram Bot + Watcher Engine в одном процессе
  bot/
    handlers.py                 # обработчики команд/кнопок
    keyboards.py                 # inline-клавиатуры
    states.py                     # FSM-состояния диалогов
    middleware.py                  # доступ только owner_chat_id
    formatting.py                   # текстовые шаблоны сообщений
main.py                             # точка входа (запускается Task Scheduler'ом)
deploy/register_task.ps1             # регистрация задачи в Планировщике Windows
tests/                                 # pytest: scheduler, db, parser, captcha, notifications
```

## Установка

1. Python 3.11+ должен быть установлен и доступен в `PATH`.
2. Установить зависимости:

   ```powershell
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   playwright install chromium
   ```

3. Скопировать `.env.example` в `.env` и заполнить:

   ```
   BOT_TOKEN=<токен от @BotFather>
   OWNER_CHAT_ID=<ваш Telegram user id, например от @userinfobot>
   ```

4. Запустить бота (окно Chromium откроется и должно оставаться открытым —
   headless-режим намеренно не используется, см. «Антидетект» ниже):

   ```powershell
   python main.py
   ```

5. В Telegram отправить боту `/start` — откроется главное меню.

## Использование

Главное меню:

- **📦 Мои товары** — список отслеживаемых профилей поиска, карточка
  каждого с изменением/паузой/принудительной проверкой/историей/удалением.
- **➕ Добавить товар** — пошаговый диалог: ссылка на поиск → название →
  максимальная цена (опционально) → стоп-слова (опционально) →
  подтверждение с пересчитанной частотой проверки.
- **⏸ Пауза всех / ▶️ Возобновить всё** — глобальная пауза (та же кнопка
  используется и для ручного выхода из капча-бэкоффа).
- **⚙️ Настройки** — digest-режим и интервал группировки, тихие часы,
  расширенно — общий бюджет запросов.
- **📊 Статистика** — сводка по каждому активному товару, счётчик
  ошибок/капч за 24 часа, аптайм процесса.

При добавлении нового товара первый проход по нему не шлёт уведомления по
всем уже существующим объявлениям — бот один раз сообщает «добавлен товар,
сейчас N объявлений» и с этого момента уведомляет только о новых.

## Общий бюджет запросов (п.7 ТЗ)

Ключевое требование — суммарная частота обращений к Avito не растёт
линейно от числа добавленных товаров. Все активные профили стоят в
круговой очереди; между любыми двумя последовательными проверками
выдерживается `request_budget_seconds` (± джиттер). Эффективная частота
проверки конкретного профиля = `request_budget_seconds × количество
активных профилей`. При добавлении товара бот сразу показывает
пересчитанную оценку.

## Антидетект (п.8 ТЗ)

- Playwright persistent context (сохранённый профиль браузера в
  `data/browser_profile`, не свежий инкогнито при каждом запуске).
- Без headless-режима.
- Случайный джиттер вокруг `request_budget_seconds`.
- Лёгкая имитация поведения: случайный скролл на 1–3 карточки, пауза
  1–3 секунды.
- Один браузерный контекст, без параллельных вкладок/потоков.
- Анонимный режим — без логина в аккаунт Avito.
- Тихие часы (опционально): не останавливают проверки полностью, но
  снижают частоту в заданном диапазоне.
- При обнаружении признаков капчи/блокировки — немедленная остановка
  **всех** проверок, экспоненциальный бэкофф (старт ~15 мин, ×2 за
  каждую последующую капчу, потолок 6 часов), тревожное сообщение
  владельцу. Возобновление — по истечении тайм-аута или явной командой
  «▶️ Возобновить всё».

## Обработка ошибок (п.11 ТЗ)

- Единичные сетевые сбои/таймауты не шлют уведомление — только если
  подряд случилось 4 и более ошибок.
- Если ожидаемые карточки объявлений не найдены и это не легитимная
  пустая выдача — предполагается смена вёрстки Avito: HTML сохраняется в
  `logs/html_dumps/` для разбора, владельцу шлётся одно уведомление (не
  повторяется на каждом цикле, пока не восстановится).
- Состояние (профили, `seen_listings`, счётчики капчи) хранится в SQLite
  и переживает падение/перезапуск процесса.

## Развёртывание на Windows (п.12 ТЗ)

```powershell
powershell -ExecutionPolicy Bypass -File deploy\register_task.ps1
```

Скрипт регистрирует задачу Планировщика заданий с триггером «при входе в
систему» и настройками автоматического перезапуска при падении
(`RestartCount`/`RestartInterval`) — отдельный внешний watchdog не
требуется. Логи и файл состояния лежат в каталоге проекта (`logs/`,
`data/`), не в системных директориях.

Удалить задачу:

```powershell
Unregister-ScheduledTask -TaskName "AvitoWatcherBot" -Confirm:$false
```

## Тесты

```powershell
pip install -r requirements-dev.txt
pytest
```

Тесты покрывают чистую логику (планировщик, парсер, капча-эвристики,
форматирование уведомлений, SQLite-слой) без запуска реального браузера
или Telegram API.

## Оговорка (п.15 ТЗ)

Автоматический сбор данных с Avito может противоречить пользовательскому
соглашению сайта. Реализованные антидетект-меры снижают вероятность
блокировки, но не устраняют этот риск полностью.
